# 热更推送手册（国内云服务器自托管）

本项目不依赖 EAS Update、七牛云或境外 CDN。APK 内的 `expo-updates` 直接访问现有云服务器，Express 返回签名后的更新清单、JS/Hermes bundle 和图片字体资源。

用户在普通中国大陆网络下打开 App，客户端会自动检查并后台下载；首页出现「已为你更新到新版本」后，点「立即重启」或下次启动即可生效。更新服务器不可达时继续运行 APK 内置版本，不会卡住启动。

## 能热更和不能热更的内容

可以直接热更：TypeScript/JavaScript、页面、文案、业务逻辑，以及随 bundle 导出的图片和字体。

以下原生层改动必须重新打 APK：

- 新增或升级带原生代码的依赖
- 修改 Android 权限、Gradle、原生插件、应用图标或启动配置
- 升级 Expo SDK / React Native

做原生层改动时，先提升 `client/app.config.ts` 的 `version`。本项目的 `runtimeVersion` 与 app version 绑定，不同原生版本不会收到彼此不兼容的更新。

## 一、服务器首次启用（只做一次）

服务端需要这些环境变量；可复制 `server/.env.example`，并把 `/opt/roam-dlut` 换成服务器上的真实项目目录：

```dotenv
PORT=9091
PUBLIC_BASE_URL=http://1.92.120.33:9091
OTA_PUBLIC_BASE_URL=http://1.92.120.33:9091
OTA_UPDATES_DIR=/opt/roam-dlut/server/data/updates
OTA_PRIVATE_KEY_PATH=/opt/roam-dlut/server/data/ota/keys/private-key.pem
STORAGE_PROVIDER=local
SERVER_SECRET=请换成随机长字符串
```

在本机 PowerShell 中上传私钥。SSH 会提示输入密码，密码只在终端输入，不要写进仓库或聊天：

```powershell
ssh <SSH用户名>@1.92.120.33 "mkdir -p /opt/roam-dlut/server/data/ota/keys && chmod 700 /opt/roam-dlut/server/data/ota/keys"
scp server/data/ota/keys/private-key.pem <SSH用户名>@1.92.120.33:/opt/roam-dlut/server/data/ota/keys/private-key.pem
ssh <SSH用户名>@1.92.120.33 "chmod 600 /opt/roam-dlut/server/data/ota/keys/private-key.pem"
```

私钥位于被 Git 忽略的 `server/data/`，不会 push 到 GitHub。请另外离线备份；丢失后，已经安装的 APK 无法信任新密钥签发的更新。

服务器拉取本次代码后安装、构建并重启现有进程：

```bash
cd /opt/roam-dlut
pnpm install --frozen-lockfile
pnpm --filter=./server run build
```

如何重启取决于服务器当前使用的是 systemd、PM2 还是其他进程管理器。必须确保进程工作目录和上述绝对路径正确，并加载 `server/.env`。

验证接口：

```text
http://1.92.120.33:9091/api/v1/updates/health
```

返回 `{"enabled":true,"runtimes":[]}` 或包含 `1.0.0` 即表示 OTA 路由已上线。

## 二、构建热更新基座 APK（只需首次或原生改动后）

GitHub 仓库变量 `BACKEND_BASE_URL` 设置为：

```text
http://1.92.120.33:9091
```

push 到 `main` 后，GitHub Actions 会构建 APK 并发布到 `latest` Release。Workflow 会强制检查：

- APK 内不是 localhost 地址
- `expo-updates` 已启用
- OTA URL 已写入 AndroidManifest
- runtimeVersion 已生成
- 公钥证书和验签元数据已内置

用户必须先安装一次这个新版基座 APK；此前的 r21 没有有效的自托管更新地址，无法通过热更把自己升级成热更基座。

## 三、日常发布热更新

以下命令在仓库根目录的 Windows PowerShell 中运行：

```powershell
$env:EXPO_PUBLIC_BACKEND_BASE_URL = "http://1.92.120.33:9091"
pnpm ota:export -- --message "本次更新说明"
```

脚本会读取 app version 作为 runtimeVersion，运行 Android `expo export`，校验导出结果，并原子写入：

```text
server/data/updates/<runtimeVersion>/<毫秒时间戳>/
```

找出刚生成的目录：

```powershell
$runtime = "1.0.0"
$release = Get-ChildItem "server/data/updates/$runtime" -Directory |
  Where-Object Name -Match '^\d+$' |
  Sort-Object { [long]$_.Name } -Descending |
  Select-Object -First 1
$release.FullName
```

先上传到远端临时目录，再一次性改名，避免用户下载到半套文件：

```powershell
$sshUser = "<SSH用户名>"
$sshHost = "1.92.120.33"
$remoteRuntime = "/opt/roam-dlut/server/data/updates/$runtime"
$incoming = ".incoming-$($release.Name)"

ssh "${sshUser}@${sshHost}" "mkdir -p '$remoteRuntime'"
scp -r $release.FullName "${sshUser}@${sshHost}:$remoteRuntime/$incoming"
ssh "${sshUser}@${sshHost}" "test -f '$remoteRuntime/$incoming/metadata.json' && test -f '$remoteRuntime/$incoming/release.json' && mv '$remoteRuntime/$incoming' '$remoteRuntime/$($release.Name)'"
```

最后访问健康接口确认 runtime 已出现。已经安装热更基座的用户下次打开 App 会自动收到更新；服务端不需要重启。

注意：`EXPO_PUBLIC_BACKEND_BASE_URL` 是编译期变量。导出脚本会拒绝 localhost，但仍应在每次发布前确认它指向正确的公网服务器。

## 四、紧急回滚到 APK 内置版本

```powershell
$env:EXPO_PUBLIC_BACKEND_BASE_URL = "http://1.92.120.33:9091"
pnpm ota:rollback -- --message "紧急回滚说明"
```

它会生成一个新的回滚 release。按第三节同样上传该目录后，客户端会收到 Expo 标准 `rollBackToEmbedded` 指令。

如果只是想恢复某个旧 OTA，更稳妥的做法是把旧代码重新导出成一个新 release，而不是覆盖或删除已经发布的资源目录。

## 五、上线前检查

- 云安全组与系统防火墙已放行 TCP 9091
- `GET /api/v1/updates/health` 在手机移动网络下可访问
- 私钥权限为 600，且未进入 Git
- 手机安装的是新的热更基座 APK，不是 r21
- 先推一个只改明显文案的测试 OTA，确认「下载 → 立即重启 → 新文案生效」完整链路

当前的公网 IP + HTTP + 9091 足够用于演示和小规模使用，并且不需要梯子。正式面向大量用户时，建议再接入中国大陆可访问的备案域名、HTTPS 443、监控和多机/对象存储冗余，以消除单 IP、单机磁盘和非标准端口的单点风险；代码签名已经能防止 HTTP 链路中的更新包被篡改。
