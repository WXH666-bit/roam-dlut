# 热更推送手册（EAS Update）

JS 层改动（界面/文案/逻辑）通过 EAS Update 推送，用户打开 App 自动检查、后台下载，首页出现「已为你更新到新版本」横幅，点「立即重启」或下次启动时生效，**无需重装 APK**。原生层改动仍走 CI 重打包。

以下命令均在 **Windows PowerShell**、仓库的 `client` 目录下执行。

## 第一步 开通（一次性）

1. 注册免费账号：https://expo.dev
2. 登录并创建项目：

   ```powershell
   cd client
   npx eas-cli login
   npx eas-cli init
   ```

3. 记下 `init` 输出的 **Project ID**，填入 `client/eas.json` 的 `projectId` 字段（替换 `TODO_EAS_PROJECT_ID`）。
4. `commit + push`，等 CI 出下一个 APK——这个 APK 就是**热更基座**，在手机上覆盖安装一次。

> eas.json 是唯一需要维护 ID 的地方；占位符未替换时打包出的 APK 无热更行为，与接入前完全一致。

## 第二步 日常推送（只改了 JS/界面/文案，不重打 APK）

```powershell
cd client
$env:EXPO_PUBLIC_BACKEND_BASE_URL = "http://1.92.120.33:9091"
npx eas-cli update --branch production --message "本次更新说明"
```

⚠️ **`EXPO_PUBLIC_BACKEND_BASE_URL` 是编译期内联变量，推送前必须按上面设置**。忘了设置就推，推出去的包连不上服务器，只能再推一次正确的覆盖。

## 第三步 何时必须重打 APK

以下改动属于**原生层**，热更推不了：

- 新增或升级原生依赖（如 expo-updates、react-native-geolocation-service 这类带原生代码的包）
- 改 Android 权限（app.config.ts 的 permissions）
- 改 gradle / 打包配置 / 图标闪屏等资源

流程：

1. 把 `app.config.ts` 的 `version` 递增（如 `1.0.0` → `1.0.1`）——runtimeVersion 绑定的就是它，不递增会把新 JS 推到不兼容的旧原生层上
2. `commit + push` 走 CI 出新 APK，手机覆盖安装
3. **出包后必须重新执行一次第二步的热更推送**——runtimeVersion 变了，之前的推送对新 APK 无效

## 附：查看推送历史

```powershell
npx eas-cli update:list
```
